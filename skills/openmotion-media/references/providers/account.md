# OpenDesign account models

Checked on 2026-11-27 against [OpenDesign source](https://github.com/nexu-io/open-design/tree/59e4f2ae85de7e7318a5e6bdcf3a34584c4b7582) and `@powerformer/vela-cli@0.1.10`. The CLI owns browser authorization, credential persistence, billing/workspace control commands, and text model discovery; OpenMotion does not reproduce private authentication endpoints or bundle its binary. All account media generation (image, video, speech, music, sound effects, 3D, and world) submits, polls, and downloads directly via the OpenDesign media HTTP API (`/api/v1/media/*`) using the account control key.

The user signs in through **Settings → Model providers → OpenDesign → Sign in with OpenDesign** and completes authorization in their browser. On first use, each workspace prepares the pinned connector in its private data directory (`<data directory>/account/runtime`). Account credentials, session identity and cached models live in the per-user OpenDesign account directory (or `MOTION_ACCOUNT_DIR`, or the workspace's own `account/` under the system temporary directory) so every OpenMotion workspace for the same user shares one sign-in; credentials are not copied from other apps, and are never returned to the Agent. Account models appear under provider ID `account`, alongside BYOK. A successful login establishes identity, not billing or generation acceptance; inspect refreshes billing and returns advisory mediaEntitlement, normalized plan and hasBalance, without raw dollar balances. Free and Go report not-included whatever their balance, because those plans entitle text models only and credits never unlock media models; available stays true for Go text models. unknown (billing failures, an unrecognized plan) continues to discovery. Free or Go users can click **Upgrade to Plus** directly on the same OpenDesign page. Follow [setup guidance](../setup.md) for alternatives.

Call `openmotion_media_use` with `action=inspect`, then `action=reference, provider=account`, then `action=models, provider=account, refresh=true`. Discovery uses the connector's remote model and media catalogues, including their enabled flags (and probes `/api/v1/media/models?include_audio=true` with the account control key so newly activated `audio_sound_effects` models such as `elevenlabs-sound-v3` appear immediately). For signed-in accounts, `elevenlabs-v3`, `byteplus-tts-2` and `elevenlabs-music-v2` are also included as built-in (`source: "builtin"`) audio entries whenever the remote media catalogue omits them; a live catalogue entry (including `enabled: false`) takes precedence, and built-in entries do not prove plan entitlement. Use only returned IDs and the provider's model parameter documentation; no model name or entitlement is guessed.

```json
{"action":"generate","requestId":"account-image-one","model":"account:CATALOGUE_MODEL_ID","modality":"image","prompt":"A ceramic cup","parameters":{}}
```

Image parameters supported by the account boundary: `aspect_ratio`, `resolution`, `quality`, `size`, and `background` where the model's `generationOptions` list it (GPT Image 2.6 accepts `"transparent"` for background removal). On the wire, the media API requires `aspect_ratio` and `resolution` together as an `output` pair published for the active operation (`generations` vs `edits`). When the synced catalogue publishes `capabilities.profiles`, OpenMotion validates against the active envelope and automatically completes a missing half from the published default (or first matching) pair before submission, while rejecting unpublished ratios, resolutions, or pairs before submission. `size` cannot be combined with `aspect_ratio`, `resolution`, or `output`, and `quality` must be one of the model's values; even when no `profiles` are published, OpenMotion rejects incomplete `aspect_ratio`/`resolution` pairs before submission. Omit them to use the model default. Video uses `modality=video`, and accepts `ratio`, `resolution`, `duration`, `generate_audio`. Speech uses `modality=audio`, `mode=text-to-speech`, and `parameters.voice`. For `elevenlabs-v3` and `byteplus-tts-2`, the `models` action lists checked voices and the default voice in `generationOptions`; pick one that suits the language and tone, and omit it only to use the default. Another voice ID belonging to that model is passed through unchecked. Other speech models require a voice ID belonging to that model. Music uses `modality=audio`, `mode=text-to-audio`, and accepts an optional whole-second `parameters.duration`; the catalogue publishes no duration range, so the account service decides which lengths it accepts. Sound effects (such as live `account:elevenlabs-sound-v3`, capability `sound-effects`) also use `modality=audio`, `mode=text-to-audio` (`audioKind: "sfx"`), and accept `parameters.duration_seconds` (`0.5–30`), `parameters.loop` (boolean), and `parameters.prompt_influence` (`0–1`) with a concise prompt (**≤ 400 characters**, hard cap 450). When `3d_generations` (`tripo-3.0`) or `world_generations` (`worldlabs-atlas`) are exposed live by the account gateway, invoke them through `openmotion_capability_run` with `capabilityId="3d-asset"` (operations `text_to_model`, `image_to_model` with 1 pinned image reference, `rig`, `rig_retarget` with `mixamo-idle`/`mixamo-walk`/`mixamo-run`, plus `retarget`/`decimate`/`texture`/`convert`; quality presets `prop-low`/`hero-balanced`/`hero-high`; never pass `quad: true`) or `capabilityId="3d-world"` (World Labs Atlas v2: text-only default `atlasTextToImage` returning a scene PNG frame such as `frames_0_image`, `images2PosedRGBD` from reference images, `atlasGenerate` with required `parameters.contextFrames` + `parameters.targetCameras`, `atlasChisel`, `posedImages2Splats`, and `splats2Mesh` returning `.glb`; imports the selected `.glb` or image/video artifact and preserves all descriptors in `version.result.artifacts`). Unsupported parameters fail before submission. The account catalogue lists the same video models as OpenDesign Cloud; choose between them as in [Choosing a video model](opendesign.md#choosing-a-video-model), and follow the same [three-tier parameter priority and OpenDesign Cloud API docs escape hatch](opendesign.md#parameter-priority-and-unknown-model-escape-hatch) (live discovery first, local fallback only for missing fields, and official OpenDesign Cloud API docs only on empty capabilities or unexpected `400`/`422`—never copy wire fields from upstream vendor API docs).

Image editing and first-frame video: an image model returned with `supportsImageReference: true` (its catalogue entry publishes `edits` for this account) edits input images, up to the `maxInputImages` it reports (the same per-model limits as OpenDesign Cloud, for example one for Seedream 5.5), and a video model returned with `maxInputImages: 1` (its catalogue entry publishes `max_input_images`) accepts one input image as its first frame. Queue either with `openmotion_assets_use` `action=generate`, `model=account:CATALOGUE_MODEL_ID`, and pinned `references` entries (`assetId` and `versionId`); a first-frame video takes exactly one. The image is snapshotted when queued and must be a PNG, JPEG or WebP under 2 MiB; the original asset is not modified. Last-frame and multi-reference video inputs are not supported through the account provider yet.

All account media jobs submit directly to the OpenDesign media HTTP API with the signed-in profile's control key (exactly as an OpenDesign Cloud key would): image generation/editing (`/api/v1/media/images/generations` or `/images/edits`), video generation (`/api/v1/media/videos/tasks`, uploading a first-frame image via `/uploads`), speech (`/api/v1/media/audio/speech`), music (`/api/v1/media/audio/music`, mapping `duration` to `music_length_ms`), sound effects (`/api/v1/media/audio/sound-effects`), and spatial 3D/World capability runs (`/api/v1/media/3d/tasks`, `/api/v1/media/worlds/tasks`). OpenMotion saves the returned `task_id` and polls only that original task directly (`/images/tasks/{id}`, `/videos/tasks/{id}`, `/audio/tasks/{id}`), downloading results without forwarding credentials on redirects or signed URLs. Images and audio with `size_bytes` retain verified partial bytes for bounded retries and `openmotion_job_manage(action="resume")` (Range/If-Range requires matching asset identity, a verified local checkpoint and a strong ETag; invalid partial files or validators restart the same download, never generation); videos resume polling/downloading the original `task_id` without re-submitting. Signed URLs stay in memory and are refreshed through original-task reads. Long-running `3d-asset` / `3d-world` calls checkpoint remote task IDs locally: if an MCP client times out, re-invoke `openmotion_capability_run` with the exact same `requestId` and arguments to resume without re-billing. The downloaded file is validated before adding it as a new library asset version; an older project-direct job imports into its original project instead. Poll with the tool that queued the job, as the [job procedure](../jobs.md) describes, and place a selected library result with `openmotion_assets_use action=import_to_project`. Do not submit another task to check progress. Local requestId replay returns the original job.

Account session identity is captured when queuing. Signing out or switching identity prevents an old queued task from submitting under a new account. If `inspect` reports the `account` provider unavailable because the OpenDesign sign-in expired, open the sign-in handoff from [setup](../setup.md) and ask the user to sign in again on the **OpenDesign** provider page. Account tasks queued before that fail without submission; resubmit them after the new sign-in. Failed requests keep only bounded service error codes and never expose raw upstream response text or credentials. Check account connectivity, available credits and original task history before retrying. Cancellation stops local work; it does not prove a remote cancellation or refund. Interrupted/uncertain paid requests are never automatically resubmitted or routed to another provider.

For plan or balance failures, follow [account recovery](../jobs.md#opendesign-account-recovery).
